# 太极智练答辩可能问题清单（详细回答版）

适用项目：太极智练 - AI 太极拳动作评测与中原武术文化研学平台  
适用时间：赛前答辩排练、现场问答准备  
使用方式：本文件不是“论文式背诵稿”，而是“评委问什么，我们怎么稳稳接住”的口径库。回答时可以根据时间压缩，但不要改变核心边界：当前是比赛原型，AI 姿态识别与评分逻辑已形成技术路径，部分数据用于原型演示，后续需要专家样本校准。

## 0. 先背这一组

### 0.1 30 秒项目介绍

各位老师好，我们的项目叫“太极智练”，全称是 AI 太极拳动作评测与中原武术文化研学平台。它不是一个单纯展示太极文化的网页，而是把用户的身体动作作为文化学习入口。用户可以通过摄像头或上传视频进行太极跟练，系统提取人体关键点，围绕姿态标准度、重心稳定性、节奏匹配度和肢体协调性给出训练反馈。同时，我们设计了虚拟推手对练、太极数字小人、招式课程、中原武术文化地图和训练报告，让用户在“练、评、玩、学”的过程中理解太极拳和中原武术文化。

### 0.2 1 分钟项目介绍

我们这个项目主要解决两个问题。第一个是太极拳学习中的反馈不足。很多初学者跟着视频练，但是不知道自己哪里做得不标准，例如重心是否偏移、手臂和腰胯是否同步、节奏是否过快。第二个是传统文化传播中的互动不足。很多文化展示类网页只是图文和视频，用户参与感比较弱。

针对这两个问题，我们设计了“太极智练”平台。技术上，平台通过摄像头或视频输入获取用户动作，利用人体姿态识别提取肩、肘、腕、髋、膝、踝等关键点，再和标准动作模板对比，形成四维评分和纠错建议。交互上，平台加入虚拟推手对练，把“借力化力、虚实转换、重心控制”等抽象概念转化成可点击、可判断、可反馈的体验。文化上，我们把陈家沟、少林寺、河洛文化等中原武术文化节点做成地图和卡片，并和训练结果绑定，实现“练中学、学中悟”。当前作品是可运行的 Web 原型，后续会重点补充标准动作库、专家评分数据和真实用户测试。

### 0.3 评委最可能先问的三句话

**问：你们的 AI 到底在哪里？**  
答：AI 主要体现在三个层面。第一是人体姿态识别，我们使用 MediaPipe Pose Landmarker 这类姿态估计技术，从摄像头或视频中提取人体关键点。第二是动作分析与评分，我们不是直接给一个分数，而是把太极动作拆成姿态、重心、节奏、协调四个维度，进行可解释评测。第三是 AI 教练建议，系统把评分、招式要点和常见错误组织成训练上下文，再由本地规则或大模型生成更像教练的纠错建议。

**问：你们这个分数真实吗？**  
答：我们会明确区分“原型演示评分”和“专业裁判评分”。当前系统的分数主要用于展示技术路径和训练辅助反馈，不等同于正式比赛裁判分。它的逻辑是合理的：从人体关键点中提取手腕跨度、膝关节角度、肩髋对齐、髋部中心摆动等特征，再映射到姿态、重心、节奏和协调四项评分。后续要做到更专业，需要引入太极拳教师标准动作视频和专家人工评分数据，对权重、阈值和纠错规则进行校准。

**问：这和普通太极网站有什么区别？**  
答：普通太极网站通常是“看文化”，以文字、图片、视频为主。我们的项目是“参与文化”，用户需要真正做动作、得到评分、进行推手互动、生成数字小人、解锁文化卡片和查看训练报告。也就是说，我们把太极拳从静态展示内容变成了可识别、可评价、可交互、可复盘的数字体验。

## 1. 项目定位与背景

### 1.1 为什么选择太极拳作为项目主题？

太极拳非常适合智能文化赛道，因为它既是传统武术文化，又是可以被身体动作表达和计算机视觉分析的运动形式。相比单纯的历史文化介绍，太极拳有明确的动作过程，比如起势、云手、单鞭、白鹤亮翅、收势，这些动作可以通过人体关键点、骨架连线、关节角度和重心轨迹进行数字化表达。同时，太极拳背后还有“阴阳相生、刚柔并济、动静结合、虚实转换”等文化内涵，适合和中原武术文化研学结合。因此，我们选择太极拳，是希望让 AI 不只是做识别工具，而是成为传统文化体验方式的一部分。

### 1.2 项目主要解决什么痛点？

我们主要解决两个痛点。第一个是学习反馈不及时。传统太极学习依赖老师示范和纠正，但在一对多教学或线上自学场景中，老师很难持续观察每个学生的动作细节，学习者也很难判断自己是否真正做到位。第二个是文化传播互动不足。很多传统文化网页主要是图文、视频和地图展示，用户只是浏览信息，很难形成身体参与和情感记忆。我们希望通过 AI 跟练、虚拟推手、数字小人和文化解锁，让用户不是被动看文化，而是在动作训练中体验文化。

### 1.3 为什么项目符合“智能文化”赛道？

智能文化赛道强调的是智能技术与文化内容的结合。我们的项目中，“智能”体现在姿态识别、关键点分析、动作评分、交互判定和大模型建议；“文化”体现在太极拳招式、中原武术地图、推手思想、文化卡片和研学路线。它不是把 AI 技术和文化内容简单放在同一个页面，而是让 AI 技术直接服务于文化体验：用户通过练习动作触发评分，通过推手互动理解借力化力，通过训练报告解锁文化内容。这种融合关系比较符合赛道主题。

### 1.4 为什么不做普通机器人实体，而做 Web 平台？

我们选择 Web 平台主要有三个原因。第一，Web 的传播门槛低，用户不需要安装软件，在电脑、平板或大屏上都可以展示，适合比赛答辩和文旅展厅场景。第二，浏览器已经支持摄像头调用、视频播放、Canvas 绘图、音频节拍和前端 AI 模型加载，可以承载当前原型。第三，Web 平台便于后续扩展到小程序、大屏互动或机器人终端。也就是说，我们现在做的是“智能文化体验平台”的核心软件原型，未来可以接到实体机器人、体感设备或数字展厅中。

### 1.5 用户群体是谁？

我们的目标用户可以分为五类。第一类是高校学生，适合在体育课或传统文化课程中使用。第二类是太极拳初学者，他们需要低门槛的动作反馈。第三类是青少年研学用户，他们更容易被互动和解锁机制吸引。第四类是文旅展厅或非遗体验馆游客，他们可以通过大屏快速体验中原武术文化。第五类是传统文化爱好者和大众健康用户，他们可以把平台作为轻量化训练和文化学习工具。

### 1.6 项目名称“太极智练”怎么解释？

“太极”说明项目对象是太极拳和中原武术文化，“智练”有两层含义：一是智能训练，通过 AI 姿态识别和评分帮助用户练动作；二是智慧研学，通过文化地图、课程和卡片让用户理解动作背后的文化。这个名字希望表达的是“用智能技术帮助用户练太极、懂太极、传播太极”。

## 2. 项目功能与完整流程

### 2.1 平台有哪些核心功能？

平台目前有六个核心功能。第一是 AI 太极跟练评测，用户可以摄像头跟练或上传视频，系统显示骨架、评分和纠错建议。第二是虚拟推手对练，系统虚拟小人出招，用户点击对应身体部位完成化解。第三是我的太极数字小人，用户上传练习视频后生成水墨骨架和动作轨迹。第四是太极招式课程，把起势、云手、单鞭、白鹤亮翅、收势拆成动作要点和常见错误。第五是中原武术文化地图，展示陈家沟、少林寺、河洛文化、开封民俗、郑州数字文旅等节点。第六是训练报告中心，展示综合评分、四维能力、趋势图和个性化建议。

### 2.2 用户完整体验流程是什么？

用户进入平台后，首先在首页了解项目定位和核心能力，然后选择一个招式，例如“云手”。进入 AI 跟练后，用户可以打开摄像头或上传练习视频，系统尝试识别人体关键点，并把用户动作和标准动作模板进行对比，输出姿态、重心、节奏和协调四项评分。训练结束后，用户可以生成训练报告，看到综合表现、短板和下一步建议。与此同时，用户还可以进入虚拟推手模块，通过点击热点体验借力化力；也可以上传视频生成数字小人；完成训练或互动后，系统会解锁对应文化卡片，引导用户了解陈家沟太极、少林武术和河洛文化等内容。

### 2.3 首页总览页面要讲什么？

首页是整个项目的“项目名片”。答辩时不用在首页停留太久，主要讲清楚三件事：第一，项目全称是 AI 太极拳动作评测与中原武术文化研学平台；第二，核心理念是“边练、边评、边玩、边学”；第三，平台不是单一页面，而是从动作输入到训练报告、从推手互动到文化解锁的完整闭环。首页可以用来快速建立评委对项目的整体印象。

### 2.4 AI 跟练页面要讲什么？

AI 跟练页面是技术基础模块。我们要强调用户不是只看标准视频，而是把自己的动作输入系统。系统会尝试识别人体骨架，显示用户动作状态，同时展示标准动作模板和评分面板。评分面板包括综合分和四个分项，纠错建议会根据最低分项和当前招式要点生成。例如云手动作中，如果重心稳定性偏低，系统会提示用户先放慢左右转换，让重心到位后再带动手臂。这个页面体现的是“AI 技术如何服务太极学习反馈”。

### 2.5 推手对练页面要讲什么？

推手对练页面是项目最有交互亮点的模块。太极推手中的“听劲、化劲、借力化力”对初学者来说比较抽象，我们把它转化成网页互动：系统随机发出掤、捋、挤、按等来势，用户需要在倒计时内点击肩肘、手腕、胸前、腰胯等热点部位。系统根据点击位置和反应时间判定成功或失败，并给出文化解释。这个模块不是单纯小游戏，而是把太极推手的动作逻辑和文化思想做成交互体验。

### 2.6 数字小人页面要讲什么？

数字小人模块主要用于个性化展示和训练复盘。用户上传练习视频后，平台展示“视频采样、骨架提取、轨迹平滑、水墨生成”的流程，并生成水墨风格骨架小人。它的意义在于把用户自己的动作变成可视化数字内容，而不是只看原始视频。后续接入真实姿态识别后，可以把用户视频逐帧提取关键点，再驱动数字小人动画，用于课堂展示、动作轨迹对比和训练档案。

### 2.7 招式课程页面要讲什么？

招式课程页面解决的是用户“不知道怎么练”的问题。我们选择起势、云手、单鞭、白鹤亮翅、收势五个基础招式，每个招式都包含动作目标、分解步骤、训练重点、常见错误和文化内涵。比如云手强调“腰胯带动、左右转换、圆活连贯”，常见错误是“只动手不转腰、重心不清、手臂僵直”。课程页面和 AI 跟练是连通的，用户学完要点后可以直接进入对应招式训练。

### 2.8 文化地图页面要讲什么？

文化地图页面体现项目的“中原武术文化研学”属性。地图中包括陈家沟、少林寺、河洛文化、开封民俗、郑州数字文旅等节点。我们不是简单把这些地点放在地图上，而是把它们和用户训练行为绑定。例如完成云手训练后，可以解锁陈家沟太极文化；完成推手对练后，可以理解借力化力和刚柔并济；生成训练报告后，可以关联郑州数字文旅应用。这样文化内容不再是孤立文本，而是训练过程的延伸。

### 2.9 训练报告中心要讲什么？

训练报告中心负责形成学习闭环。用户训练后，系统会把当前招式、四项评分、综合分、最低分项和训练建议整合起来，形成报告。报告中还有雷达图、趋势图、训练建议和文化解锁信息。答辩时要强调，报告中的分数在当前阶段属于原型演示和辅助反馈，不是正式专业裁判结论。它的价值是帮助用户看到“这次主要短板是什么，下一次应该练什么”。

## 3. 技术架构与实现

### 3.1 系统总体架构怎么讲？

可以把系统架构讲成六层。第一层是用户交互层，包含摄像头跟练、视频上传、点击推手、文化地图浏览和报告查看。第二层是数据采集层，采集视频流、上传视频、点击位置、点击时间、训练进度等数据。第三层是 AI 识别与分析层，负责人体关键点识别、骨架建模和动作特征提取。第四层是动作评测与决策层，负责四维评分、纠错建议和推手判定。第五层是文化融合层，把招式、文化卡片和中原武术地图结合起来。第六层是应用展示层，包括跟练、推手、数字小人、课程、地图和报告。

### 3.2 当前原型用了哪些技术？

当前原型采用 Web 技术实现，前端主要是 HTML、CSS 和 JavaScript，使用 Canvas 绘制骨架、轨迹、雷达图和动画，用 video 标签处理摄像头和上传视频，用浏览器 MediaDevices API 调用摄像头，用 Web Audio 生成练习节拍。后端是一个轻量 Node.js 服务，用于提供静态资源、读取和保存云手标准骨架校准数据，以及提供 AI 教练建议接口。姿态识别方面，原型尝试加载 MediaPipe Pose Landmarker；大模型建议方面，预留了兼容 Chat Completions 的接口。

### 3.3 为什么没有用 Vue 或 React？

报告中提到 Vue 或 React 是后续工程化方案，当前初赛原型优先考虑稳定、轻量和快速演示，所以采用原生 HTML、CSS 和 JavaScript 实现。这样做的好处是依赖少、启动快、现场风险低，也便于直接控制 Canvas、视频和摄像头。后续如果进入复赛或产品化阶段，可以把当前模块拆成组件，迁移到 Vue 或 React，增加路由、状态管理和工程化测试。

### 3.4 Node 后端服务做了什么？

Node 后端目前主要做三件事。第一，作为本地 Web 服务，提供页面、图片、视频和脚本资源，保证项目可以通过本地地址稳定访问。第二，提供 `/api/standard/yunshou` 接口，用来读取和保存云手标准骨架校准数据。第三，提供 `/api/coach` 接口，接收前端传来的训练上下文，如果配置了大模型密钥，就调用兼容 Chat Completions 的模型生成建议；如果没有密钥，就返回本地兜底建议。这种设计保证了项目在无网络或无密钥时也能演示。

### 3.5 为什么要设计 fallback 兜底机制？

比赛现场环境有很多不确定性，比如网络不稳定、摄像头权限受限、浏览器模型加载失败、大模型接口无法访问。如果项目完全依赖在线模型，一旦现场失败就无法演示。我们设计 fallback 机制，是为了保证核心交互流程始终可展示：Pose 模型加载失败时使用模拟骨架，大模型不可用时使用本地建议，摄像头不可用时使用上传视频或预制演示路径。这体现的是工程可靠性，而不是掩盖技术边界。

### 3.6 摄像头调用是怎么实现的？

前端通过浏览器的 MediaDevices API 请求摄像头权限，成功后把视频流绑定到 video 元素，再用 Canvas 在视频上绘制骨架、关键点和提示信息。用户需要保持全身入镜，系统才能稳定识别肩、肘、腕、髋、膝、踝等关键点。如果用户距离摄像头太近、光线太暗或身体被遮挡，识别质量会下降，所以页面中也会提示用户保持全身入镜。

### 3.7 Canvas 在项目中为什么重要？

Canvas 是项目的视觉和交互核心。AI 跟练中，Canvas 用来绘制用户骨架、标准骨架、轨迹和评分提示；推手模块中，Canvas 用来绘制虚拟太极小人和动作状态；数字小人模块中，Canvas 用来绘制水墨骨架、残影和轨迹；报告模块中，Canvas 用来绘制雷达图和趋势图。选择 Canvas 的原因是它适合实时绘制动态画面，并且可以和视频帧、关键点数据结合。

### 3.8 标准动作模板如何保存？

当前云手标准动作模板主要通过预制关键帧和校准数据实现。系统中预留了标准动作关键点序列，并支持通过校准界面调整头、肩、肘、腕、髋、膝、踝等点的位置，使骨架更贴合标准视频。校准后的数据可以保存为 JSON，后续加载时继续使用。未来更完整的方案是请专业老师录制每个招式的标准视频，用姿态识别模型离线提取关键点序列，再作为标准模板。

### 3.9 为什么标准动作模板很重要？

因为动作评分必须有参照物。没有标准动作模板，系统只能判断用户是否被识别出来，不能判断动作是否接近目标招式。标准模板提供了每个招式在关键时间点的姿态、重心、节奏和关节角度参考。用户动作和标准模板对齐后，才能计算姿态相似度、重心偏移、节奏差异和协调性。因此，标准动作库建设是项目后续提升专业性的关键。

### 3.10 项目如何处理中文文化内容和视觉风格？

页面整体采用中文表达和水墨太极视觉风格。视觉上使用水墨山水、太极圆、骨架点线和科技感面板结合，目的是让传统文化与 AI 技术在视觉上统一。内容上，课程、文化卡片和报告都使用中文，重点解释太极动作要点和中原武术文化。后续可以继续引入更权威的文化资料和教师审核，避免文化表达过度简化。

## 4. AI 姿态识别与骨架建模

### 4.1 什么是人体姿态识别？

人体姿态识别就是从图像或视频中检测人体关键点，并根据关键点构建人体骨架。比如系统可以识别头、肩、肘、腕、髋、膝、踝等位置，再把这些点连接起来形成骨架结构。对太极拳来说，这些关键点可以反映手臂开合、腰胯转换、下肢支撑、身体中轴和动作节奏，因此是动作评测的基础。

### 4.2 项目使用哪些关键点？

项目重点关注头部、左右肩、左右肘、左右腕、左右髋、左右膝、左右踝，部分场景还会使用脚部关键点。这些点基本覆盖了太极拳动作评测中最重要的身体结构：肩肘腕对应上肢运行，髋膝踝对应下肢步法和支撑，肩部中心与髋部中心可以近似反映身体中轴，髋部中心轨迹可以近似反映重心变化。

### 4.3 为什么这些关键点可以评价太极动作？

太极拳虽然有内在劲力和呼吸要求，但从视频分析角度看，初步评测可以先关注外在动作质量。比如云手是否只动手不转腰，可以通过手腕轨迹和肩髋关系观察；重心是否稳定，可以看髋部中心和膝踝支撑关系；动作是否协调，可以看手腕高度、膝关节角度、肩髋对齐和运动节奏。关键点不能完全替代专业老师，但能提供可计算、可解释的辅助反馈。

### 4.4 当前是否真正接入了姿态识别模型？

当前原型中已经预留并尝试加载 MediaPipe Pose Landmarker，用于摄像头或视频模式下的人体关键点识别。同时，为了保证比赛现场稳定，我们也保留了模拟骨架和规则评分。答辩时要诚实说明：当前阶段是比赛原型，能够展示姿态识别技术路径和部分实时识别能力，但评分结果仍属于辅助反馈和原型演示，后续需要更多标准动作数据和实测校准。

### 4.5 为什么选择 MediaPipe Pose？

MediaPipe Pose 是比较成熟的人体姿态识别方案，适合 Web 原型快速接入，能在浏览器中提取人体关键点。我们选择它的原因是部署门槛相对低，实时性较好，社区资料较多，适合比赛阶段验证“摄像头输入 - 关键点识别 - 骨架绘制 - 动作分析”的流程。后续如果需要更高精度，也可以替换或补充其他姿态估计模型。

### 4.6 关键点归一化为什么必要？

不同用户的身高、体型、站位和摄像头距离不同，画面中的人体大小会变化。如果直接比较像素坐标，离摄像头近的人手腕距离更大，可能被误判为动作幅度更大。因此需要用肩宽、髋宽或躯干长度作为尺度，把不同用户的关键点转换到相对坐标或统一尺度下。这样评分更关注动作结构，而不是用户离镜头远近。

### 4.7 如何估计重心？

严格的物理重心需要三维人体模型和质量分布，普通摄像头很难精确计算。我们的原型采用近似方法：用左右髋的中点作为身体重心的主要参考，同时结合肩部中心、双脚位置和髋部中心在一段时间内的摆动来判断重心稳定性。这个方法不能等同于专业生物力学测量，但足以在训练辅助中提示“重心左右转换是否过大、身体中轴是否偏移”。

### 4.8 如何判断节奏是否匹配？

节奏匹配可以通过用户关键点运动速度、动作进度和标准动作时间轴之间的差异来判断。当前原型中用运动量和标准模板运动特征做基础对比，后续可以引入动态时间规整，也就是 DTW，把用户动作序列和标准动作序列进行时间对齐。这样即使用户整体稍快或稍慢，也能比较关键阶段是否对应，从而更合理地判断节奏问题。

### 4.9 如何处理关键点抖动？

摄像头识别出的关键点会有一定抖动，特别是在光线不足、动作遮挡或模型置信度低时。项目中可以通过连续帧平滑减少噪声，例如使用上一帧和当前帧的加权平均。平滑后骨架视觉更稳定，评分也不会因为单帧异常大幅波动。后续还可以加入置信度过滤、异常点剔除和短时间窗口平均。

### 4.10 识别受哪些环境因素影响？

主要受光照、背景、摄像头角度、人体是否完整入镜、衣服颜色和身体遮挡影响。比如用户只露出上半身，就无法判断下肢支撑和重心；背景复杂或光线很暗，关键点识别也会不稳定。因此实际使用时需要提示用户站在光线充足、背景简洁的位置，保持全身入镜。后续还要做不同环境下的鲁棒性测试。

### 4.11 2D 姿态识别是否足够？

2D 姿态识别可以支持初步训练反馈，尤其是正面、全身、固定机位场景下的太极基础动作。但它也有局限，例如无法准确感知前后深度、身体旋转和遮挡关系。我们当前选择 2D 是为了初赛阶段低成本、可展示、易部署。后续如果要提升专业性，可以结合多视角摄像头、深度相机或 3D 姿态估计。

### 4.12 如果用户做的是不同流派太极，系统会不会误判？

这是一个真实问题。不同流派、不同老师的动作细节会有差异。我们的回答是：当前原型先以基础招式和标准模板为参考，适合初学辅助训练；后续可以建立多套标准模板，例如陈氏、杨氏或校园教学版，用户选择对应模板。评分不应该追求唯一标准，而是围绕所选教学目标进行比较。

## 5. 动作评分模型

### 5.1 为什么设置四个评分维度？

太极拳不是单纯摆出一个姿势，而是一个连续、平稳、协调的动作过程。因此我们设置四个维度：姿态标准度看动作形态是否接近标准；重心稳定性看身体是否平稳、重心是否乱晃；节奏匹配度看动作速度和标准时间轴是否一致；肢体协调性看手、腰、胯、腿是否配合。这样比只给一个总分更可解释，也更符合太极拳“缓、稳、圆、连、协调”的特点。

### 5.2 综合评分公式怎么讲？

研究报告中给出的公式是 `Score = 0.30Sp + 0.25Sb + 0.25Sr + 0.20Sc`，展板中为了突出姿态标准度，也出现了 `0.35Sp + 0.25Sb + 0.20Sr + 0.20Sc` 的表达。答辩时可以这样解释：四个指标是确定的，权重是可调参数。初赛阶段我们用它说明评分逻辑，最终权重需要根据太极拳教师评分和真实用户数据进行校准。因此目前不把某个权重说成最终标准，而是强调“评分体系可解释、可调整、可验证”。

### 5.3 姿态标准度怎么计算？

姿态标准度主要比较用户当前姿态和标准动作模板的相似程度。可用的特征包括关键点距离、骨架向量夹角、手腕跨度、关节角度和关键点可见度。例如云手中，两手的相对位置、肩肘腕的连线、膝盖弯曲程度和身体中轴都能反映姿态是否接近标准。当前原型把这些特征映射为姿态分，后续会用更多标准样本优化阈值。

### 5.4 重心稳定性怎么计算？

重心稳定性主要关注用户在动作过程中是否平稳。系统可以用髋部中心作为近似重心参考，观察它在一段时间内的左右摆动范围，同时结合肩部中心和髋部中心是否对齐。如果髋部中心大幅晃动、肩髋偏移明显，说明用户可能重心不稳或身体侧倾。太极拳要求虚实转换清楚，但不是乱晃，因此重心稳定性是非常重要的指标。

### 5.5 节奏匹配度怎么计算？

节奏匹配度关注动作过程是否和标准动作节奏一致。比如云手不是越快越好，而是要保持圆活连贯和缓慢转换。如果用户动作突然加速、停顿或和标准视频阶段不一致，节奏分会下降。当前原型用关键点运动量和标准模板运动特征进行基础比较，后续可以用动态时间规整或阶段识别来进一步优化。

### 5.6 肢体协调性怎么计算？

肢体协调性不是看单个关节，而是看身体各部分是否配合。比如云手要求“腰胯带动，手随身行”，如果用户只是手臂摆动、腰胯没有转换，就属于协调性问题。原型中可以通过左右腕高度差、膝关节角度、肩髋对齐、手脚同步关系等特征综合判断。后续可以加入更多太极教师规则，例如“转腰先于手臂”“膝盖方向跟脚尖一致”等。

### 5.7 为什么不能直接用一个相似度分数？

如果只给一个相似度分数，用户不知道自己哪里错了。比如同样是 80 分，一个人可能是手腕高度不对，另一个人可能是重心不稳，还有一个人可能是节奏太快。太极学习需要可解释反馈，所以我们拆成四个维度。这样系统不仅能说“你得了 86 分”，还能说“当前短板是重心稳定性，建议先放慢左右转换”。

### 5.8 当前评分是否可靠？

当前评分可以作为原型演示和训练辅助反馈，但不能说已经达到专业裁判级可靠。它的可靠性来自明确的特征和规则逻辑，而不是大规模实验证明。我们后续要做的工作是：请太极教师录制标准动作，收集普通用户不同错误类型的视频，让教师人工评分，然后比较系统评分和教师评分是否方向一致，再调整权重和阈值。这是从原型走向实用系统必须补的步骤。

### 5.9 如果评委质疑“分数是写死的”，怎么回答？

可以这样答：项目中确实保留了原型演示数据和动态模拟评分，这是为了保证现场展示稳定；但我们并不是只写死一个分数。技术结构中已经包含关键点特征提取、标准模板对比、分项评分和训练报告生成。答辩时可以主动说明哪些是演示数据，哪些是实际算法路径。我们希望诚实表达原型阶段边界，而不是把演示数据包装成完整实验结论。

### 5.10 如何验证评分模型？

评分模型可以从三个方面验证。第一，用标准动作和故意错误动作对比，比如标准云手、只动手不转腰、重心偏移、节奏过快，观察对应分项是否合理下降。第二，邀请太极拳教师对同一批动作视频进行人工评分，看系统分数和专家评分趋势是否一致。第三，做用户测试，看用户根据系统建议练习后，分项评分和老师评价是否有改善。这样才能逐步证明评分模型有教学价值。

### 5.11 如果用户体型不同，评分会不会不公平？

体型差异确实会影响原始坐标，所以我们需要归一化处理，例如用肩宽、髋宽或躯干长度作为尺度基准，把动作特征转成相对值，而不是直接比较像素距离。同时，评分应设置合理容忍区间，避免对身高、臂长、柔韧性差异过度敏感。后续还可以根据用户身高、年龄、练习水平设置个性化参数。

### 5.12 如果用户动作和标准动作不完全一样，是错误吗？

不一定。太极拳有流派差异、教师风格差异和个人身体条件差异。因此我们的评分定位是“辅助训练反馈”，不是绝对裁判。系统会根据当前选择的标准模板提示偏差，但最终是否属于错误，还需要结合教学目标和老师判断。后续可以提供不同模板和难度等级，让评分更灵活。

## 6. AI 教练与大模型

### 6.1 大模型在项目中做什么？

大模型不直接负责姿态识别，也不直接给动作打分。它的作用是把结构化训练数据转化成更自然、更像教练的语言。比如系统已经知道用户当前练的是云手，重心稳定性最低，常见错误是只动手不转腰，那么大模型可以生成“本次云手整体流畅，但左右转换时重心略飘，下一轮先放慢半拍，让腰胯到位后再带动手臂”这样的建议。它提升的是反馈表达和文化解释能力。

### 6.2 没有大模型密钥怎么办？

项目设计了本地建议模式。如果没有配置大模型密钥，系统会根据当前招式、分项评分、最低分项和动作要点生成本地兜底建议。这样现场演示不依赖外部模型服务。配置密钥后，系统会自动切换到真实大模型生成。这个设计一方面保证稳定性，另一方面也便于后续扩展不同模型。

### 6.3 如何避免大模型胡说？

我们通过输入约束和提示词约束来降低风险。前端传给大模型的是结构化上下文，包括当前招式、动作要点、常见错误、分项评分、综合分、推手数据和文化内容。系统提示中要求它必须基于这些输入生成建议，不要声称已经真实诊断用户动作，不要做医学判断。实时建议还限制为短句，避免生成过长、空泛或夸张的内容。后续还可以加入教师审核过的建议模板。

### 6.4 为什么实时建议和报告建议要分开？

训练中的实时建议必须短、直接、可执行，比如“放松肩肘，重心先到脚底”。如果实时建议太长，用户正在运动时听不进去。训练后的报告建议可以更完整，分成“本次表现、下一步纠错、文化理解”等部分，帮助用户复盘。因此我们设计了规则实时建议和大模型深度建议两种形态，分别服务训练中和训练后。

### 6.5 大模型是否会上传用户隐私数据？

当前设计中，大模型接口只接收评分、招式、进度和文本上下文，不上传用户视频帧，也不上传原始图像。也就是说，视频和骨架处理主要在前端或本地流程中完成。后续如果要保存训练视频或云端分析，必须加入用户授权、数据脱敏、加密传输和删除机制。

### 6.6 为什么大模型建议要加入文化理解？

项目不是单纯运动评分工具，而是智能文化平台。太极拳动作和文化内涵是相关的，例如云手对应圆活连贯和虚实相生，推手对应借力化力和重心控制。如果报告只说动作分数，会弱化文化赛道特色。大模型可以把训练结果和文化解释连接起来，让用户理解“为什么这个动作要这样练，它背后的太极思想是什么”。

## 7. 虚拟推手对练

### 7.1 为什么虚拟推手是创新点？

太极推手本身强调听劲、化劲、借力化力和虚实转换，但这些概念对初学者比较抽象，单靠文字很难理解。我们把它设计成虚拟对练：系统出招，用户判断来势，点击关键部位，系统判定是否成功，并给出反馈。这样用户不是读“借力化力”的解释，而是在操作中体验“对方力量从哪里来，我应该稳住哪里、化解哪里”。这个模块让文化概念变成了可交互体验，所以是项目区别于普通文化网页的重要创新。

### 7.2 推手模块具体怎么判定？

每一轮推手包含系统出招、正确应对热点、反应时间窗口和反馈文本。用户点击后，系统判断两个条件：第一，点击部位是否与当前出招对应；第二，点击时间是否在合理窗口内。两个条件都满足则判定成功，增加得分和连击；如果点击错误或超时，则判定失败，并提示正确部位和动作原则。比如“按劲下压”更强调腰胯和重心控制，用户应点击腰胯相关热点。

### 7.3 推手模块是否只是小游戏？

它用了游戏化形式，但目标不是娱乐本身，而是降低太极推手概念的理解门槛。我们把传统推手中的力点判断、反应时机和动作原则转化为点击热点、倒计时、连击和反馈。游戏化只是表现方式，核心仍然是让用户理解“掤、捋、挤、按”和“借力化力”的基本逻辑。

### 7.4 为什么当前用点击，不直接识别身体动作？

这是分阶段实现策略。真实推手动作识别需要更复杂的身体动作数据、双人交互模型和更高稳定性的姿态识别，初赛阶段直接实现风险较高。我们先用点击交互验证文化概念可交互表达，让评委看到完整体验闭环。后续复赛或产品化阶段，可以把点击升级为摄像头动作响应，例如识别用户是否后坐、转腰、沉胯或抬手化解。

### 7.5 推手模块如何和训练报告结合？

推手模块会记录得分、连击、成功率、当前出招和反应时间。训练报告可以把这些数据转化为“反应判断能力、重心控制意识、推手理解程度”等反馈。例如，如果用户经常在“按劲下压”中失败，报告可以提示“需要加强腰胯稳定和重心后移意识”。这样推手不只是单独模块，而是训练闭环的一部分。

### 7.6 如果评委说推手没有真实接触，怎么回答？

可以回答：真实推手当然包含身体接触和劲力感知，Web 原型无法完全替代线下推手训练。我们的目标不是替代真实推手，而是把其中最核心的判断逻辑和文化概念做成入门级交互，让初学者先理解“力点、重心、应对部位和反应时机”。未来如果接入体感设备、双人摄像头或机器人教练，可以进一步接近真实推手体验。

## 8. 数字小人

### 8.1 为什么要做数字小人？

数字小人让用户从“我看老师怎么做”变成“我看自己怎么做”。传统视频回放信息太多，用户不一定能抓住动作问题；骨架小人可以突出关键点、轨迹和节奏，更适合训练复盘。我们采用水墨风格，是希望它既有数字人和动作分析的科技感，又符合太极文化的审美。

### 8.2 当前数字小人是否完全由用户视频生成？

当前初赛原型主要展示上传视频、骨架生成和水墨可视化的流程，部分效果仍是前端演示。我们会诚实说明这一点。完整实现路径是：用户上传视频后，系统逐帧提取人体关键点，对关键点序列做平滑和归一化，然后用 Canvas 或 SVG 驱动骨架动画，再叠加水墨残影和轨迹。当前原型已经按这个流程设计页面和状态，后续接入真实识别数据即可进一步完善。

### 8.3 数字小人有什么教学价值？

它可以帮助用户复盘动作过程。比如用户练云手时，如果手臂轨迹不圆、重心转换不连续，数字小人的轨迹会比原视频更直观地表现出来。老师也可以用它在课堂上展示学生动作轨迹，让学生看到自己的变化。对于文旅和研学场景，数字小人还可以生成个性化展示结果，增强参与感和传播性。

### 8.4 为什么不做 3D 数字人？

3D 数字人需要建模、骨骼绑定、动作重定向和实时渲染，开发成本和调试难度都比较高。初赛阶段我们选择二维水墨骨架，是为了在 Web 中稳定展示，同时保留太极文化审美。后续如果有更多时间和资源，可以升级到 3D 虚拟人、AR 展示或水墨剪影角色。

## 9. 招式课程与文化研学

### 9.1 为什么选择这五个招式？

起势、云手、单鞭、白鹤亮翅和收势都是太极基础学习中比较有代表性的动作，难度层次也比较清晰。起势适合讲松静自然和身体中正；云手适合讲腰胯带动和虚实转换；单鞭适合讲开合有度和支撑稳定；白鹤亮翅适合讲姿态舒展和动静相宜；收势适合讲调息归元和动作完整。选择这五个动作，既方便初学者入门，也方便系统展示动作评测逻辑。

### 9.2 云手为什么是重点招式？

云手非常适合作为原型重点，因为它能体现太极拳的多个核心特点：腰胯带动、左右重心转换、手臂圆活运行、节奏平稳连贯。它也容易出现典型错误，例如只动手不转腰、重心转换不清、手臂僵直。因此，用云手做标准视频、骨架模板和评分演示，能比较集中地展示项目的技术和文化价值。

### 9.3 中原武术文化地图为什么选这些节点？

我们选择陈家沟、少林寺、河洛文化、开封民俗和郑州数字文旅，是为了覆盖中原武术文化的源流、对照、思想、生活场景和现代应用。陈家沟代表太极拳源流，少林寺代表中原武术的重要符号，河洛文化可以关联阴阳变化和礼乐秩序，开封民俗体现传统体育和城市生活，郑州数字文旅代表现代数字化传播场景。这样地图不是单点介绍，而是一条研学路径。

### 9.4 少林和太极不是一个体系，为什么放一起？

我们的主题不是只讲某一个太极流派，而是中原武术文化研学。少林武术和太极拳虽然体系不同，但都属于中原武术文化的重要代表。把它们放在一起，可以形成“刚与柔、动与静、外显功法与内在调和”的对照，有利于用户理解中原武术的丰富性。项目重点仍然是太极动作评测，少林节点主要承担文化拓展作用。

### 9.5 如何避免文化内容变成堆砌？

我们采用训练解锁机制，让文化内容由用户行为触发。用户完成云手训练后，再看到虚实相生、圆活连贯的文化解释；用户完成推手对练后，再看到借力化力和以柔克刚的解释。这样文化不是一开始就塞给用户，而是在动作体验后出现，更容易理解和记住。后续还可以加入问答、路线任务和互动故事，让文化内容更系统。

### 9.6 文化内容如何保证准确？

当前原型中的文化内容主要是概念性和研学型表达，后续需要进一步引用权威资料，例如非遗资料、地方文旅资料、武术教材、太极拳教师意见和相关研究文献。我们会把文化内容分层：基础解释面向普通用户，专业解释由教师或专家审核，避免过度简化或误读传统文化。

## 10. 实验验证与数据

### 10.1 当前做了哪些验证？

当前阶段主要完成了原型功能验证和演示流程验证，也就是页面能打开、核心按钮能点击、跟练流程能走通、推手能多轮判定、数字小人能展示、文化地图能点击、训练报告能生成。算法层面，目前更多是技术路线和规则逻辑验证，还没有完成大规模真实用户实验。因此答辩时要主动说明：初赛重点是创意、技术路径和原型完整度，后续会补专家数据和用户测试。

### 10.2 后续如何收集数据？

后续数据主要来自三类。第一是标准动作数据，请太极拳教师或专业学生录制正面、全身、固定机位的标准动作视频，用于建立模板。第二是普通用户练习数据，包含标准动作和典型错误动作，例如重心不稳、手臂过快、只动手不转腰等，用于测试评分是否能区分错误类型。第三是交互数据，包括推手点击位置、反应时间、成功率、训练次数和文化卡片浏览记录，用于评价用户体验和文化传播效果。

### 10.3 如何证明评分模型有效？

可以设计对照实验。先让专业老师给一批练习视频打分或标注错误类型，再让系统对同一批视频评分。我们关注的不是绝对分数完全一致，而是趋势是否一致。例如老师认为某个视频重心不稳，系统的重心稳定性也应明显偏低；老师认为某个视频节奏过快，系统的节奏匹配度也应下降。如果系统分项评分和专家判断方向一致，就说明它具有辅助训练价值。

### 10.4 如何评价文化传播效果？

文化传播效果可以通过问卷和行为数据综合评价。问卷可以问用户是否理解了云手的虚实转换、推手的借力化力、陈家沟和太极文化的关系等；行为数据可以看用户是否愿意点击文化地图、文化卡片浏览时长、是否完成训练后继续查看文化内容。我们希望验证的是：互动式训练是否比单纯图文浏览更能提升用户兴趣和记忆。

### 10.5 如何评价推手模块？

推手模块可以从四个指标评价。第一是判定准确性，即正确点击能否成功、错误点击能否失败。第二是理解度，即用户看提示后是否知道该点哪里。第三是完成率，即用户是否愿意连续进行多轮对练。第四是反馈有效性，即失败后用户是否知道自己错在哪里。后续还可以分析反应时间和成功率变化，看用户是否通过练习提升判断能力。

### 10.6 如何评价系统可用性？

可用性评价包括页面加载速度、摄像头调用成功率、模型加载成功率、核心按钮响应、页面跳转流畅度、移动端适配和现场演示稳定性。对于比赛原型来说，稳定性非常重要，所以我们设置了 fallback 机制和预制演示路径。对于未来产品来说，还需要增加用户登录、数据存档、错误提示和无障碍体验。

## 11. 团队分工与项目管理

### 11.1 团队分工怎么回答？

不要只说“大家一起做”，要按模块说。可以回答：我们团队按项目统筹、前端开发、算法与评分、文化内容、视觉展板、演示测试几个方向分工。项目统筹负责需求拆解、进度安排和材料整合；前端负责页面布局、交互和 Canvas 可视化；算法与评分负责姿态识别方案、关键点特征和四维评分逻辑；文化内容负责太极招式、中原武术地图和文化卡片；视觉展板负责水墨风格、系统架构图和成果展示；测试演示负责现场流程、摄像头、视频和应急预案。

### 11.2 如果问你个人贡献，怎么回答？

要回答具体，不要泛泛说“我参与了项目”。例如可以说：“我主要负责 AI 跟练和评分逻辑部分，包括梳理太极动作的四个评分维度，设计姿态、重心、节奏、协调性的指标，并和前端同学一起把评分结果展示在页面和训练报告中。”如果你负责文化内容，可以说：“我主要整理了中原武术文化地图和招式文化，把陈家沟、少林寺、河洛文化等节点和用户训练行为连接起来。”一定要能接住后续追问。

### 11.3 项目开发过程中最大的困难是什么？

可以回答：最大的困难是如何在比赛原型阶段平衡“真实技术能力”和“现场展示稳定性”。姿态识别模型受网络、摄像头和环境影响，如果完全依赖真实模型，现场风险较高；但如果只做静态页面，又不能体现 AI 技术。因此我们采用了分层方案：技术上预留并尝试接入 MediaPipe Pose，评分上设计可解释模型，工程上保留模拟骨架和本地建议作为容错。这样既能展示技术路径，也能保证答辩顺利。

### 11.4 如何证明项目是自己完成的？

最好的证明不是口头说“是我们做的”，而是能讲清楚实现细节和调试过程。比如能说明页面有哪些模块、代码中如何保存招式数据、Pose 加载失败如何处理、推手点击如何判定、报告如何根据最低分项生成建议、标准骨架为什么要校准。如果评委问到某个模块，负责同学能讲出输入、处理和输出，就能证明团队真正理解项目。

### 11.5 是否使用 AI 工具辅助？

可以诚实回答：我们在资料整理、表达优化、代码辅助和答辩准备中使用了 AI 工具，但项目主题、功能设计、文化内容选择、页面实现、演示调试和最终整合由团队完成。使用 AI 工具并不等于项目不是自己的，关键是我们能解释每个模块的实现逻辑，也能根据比赛要求进行修改和落地。

## 12. 隐私、安全与伦理

### 12.1 用户视频是否会被保存？

当前原型主要面向本地演示，摄像头和上传视频主要用于浏览器端展示，不默认作为长期用户数据保存。后续如果做成正式平台，必须明确用户授权，说明视频是否保存、保存多久、用于什么目的，并提供删除机制。特别是面向青少年和校园场景时，隐私保护是必须重点考虑的。

### 12.2 大模型是否会看到用户视频？

当前设计中，大模型只接收训练上下文，例如招式、评分、最低分项、进度和文化内容，不上传视频画面或原始图像。因此大模型主要负责文本建议，不直接处理用户视频。后续如果需要云端视频分析，也应尽量使用本地骨架提取，只上传脱敏后的关键点数据，而不是完整视频。

### 12.3 系统是否会给医学建议？

不会。项目定位是太极动作学习和文化研学辅助工具，不是医疗诊断或康复系统。系统可以提示“放慢动作、保持重心稳定、注意膝盖方向”，但不能承诺治疗效果，也不能替代医生、康复师或专业教练。如果用户身体不适，应停止练习并咨询专业人士。

### 12.4 AI 评分会不会误导用户？

任何自动评分都有误差，所以我们明确把它定位为辅助反馈，不是最终权威判断。页面和答辩中都应说明当前评分是原型演示和训练辅助，后续需要教师评分校准。正式应用中还应该加入提示：AI 建议仅供练习参考，动作学习仍建议结合专业老师指导。

### 12.5 如何避免文化表达不严谨？

我们会把文化内容当作需要审核的知识内容，而不是随意生成。当前原型先做研学框架和概念表达，后续要引用权威资料，邀请太极老师或文化专家审核，尤其是涉及流派、历史源流、非遗传承和动作术语时，要避免夸大和误读。

## 13. 落地价值与推广

### 13.1 项目可以在哪里应用？

项目可以落地到校园体育教学、传统文化课程、青少年研学、文旅展厅、非遗体验馆、社区健康活动和线上太极学习等场景。在学校里，它可以作为老师的一对多辅助教学工具；在文旅展厅中，它可以作为互动大屏，让游客体验太极动作和中原武术文化；在线上，它可以帮助初学者进行轻量化自测和复盘。

### 13.2 它和线下老师是什么关系？

它不是替代老师，而是辅助老师。老师的专业判断、动作示范和文化讲解仍然不可替代，但 AI 系统可以提供高频、即时、个性化的基础反馈。比如课堂上老师无法同时盯住每个学生的重心和手臂轨迹，平台可以先给出初步分项提示，老师再针对共性问题进行讲解。这样可以提升教学效率。

### 13.3 商业模式有哪些可能？

未来可以有几种方向。第一是校园授权，作为体育课或传统文化课程辅助平台。第二是文旅展厅互动项目，为景区、博物馆、非遗馆提供大屏体验。第三是研学活动方案，把太极动作任务和文化地图结合成课程。第四是个人训练服务，提供训练档案、成长报告和个性化课程。初赛阶段我们主要展示技术和场景价值，商业化还需要继续验证用户需求和成本。

### 13.4 为什么这个项目有社会价值？

它用人工智能技术降低传统文化体验门槛，让更多年轻人以互动方式接触太极拳和中原武术文化。同时，它也倡导健康生活方式，可以服务校园体育和大众健身。更重要的是，它不是把传统文化只当作展示内容，而是让用户通过身体动作参与其中，这种方式更容易形成理解和认同。

### 13.5 项目能扩展到其他传统文化吗？

可以。我们的底层逻辑是“身体动作数字化 + 智能反馈 + 文化内容解锁”。这个框架不仅适合太极拳，也可以扩展到八段锦、五禽戏、武术套路、民族舞蹈、戏曲身段等身体性文化内容。只需要替换标准动作模板、评分特征和文化卡片，就能形成新的智能文化体验。

## 14. 后续改进

### 14.1 当前项目最大不足是什么？

最大不足是专业数据和真实验证还不够。当前原型已经有完整功能闭环和技术路径，但评分模型还需要更多专业老师标准动作、普通用户练习视频和专家评分数据来校准。我们不能把原型分数直接说成专业结论，这是后续最需要补强的地方。

### 14.2 如果进入复赛，最先改什么？

最先改三件事。第一，录制专业老师标准动作视频，建立每个招式的关键点模板。第二，收集典型错误动作样本，用于验证四维评分是否合理。第三，提高姿态识别稳定性，包括本地模型加载、摄像头适配、关键点平滑和异常处理。这样复赛时项目的“AI 真实性”和“评分可信度”会更强。

### 14.3 推手模块后续如何升级？

后续可以从点击交互升级为身体动作交互。比如系统识别用户是否完成后坐、转腰、沉胯、抬臂等动作，用这些动作来判定是否化解成功。进一步还可以加入双人对练、体感设备或机器人教练，让推手体验更接近真实训练。

### 14.4 数字小人后续如何升级？

数字小人可以升级为真实视频驱动。具体做法是逐帧提取用户视频关键点，做平滑和动作分段，再渲染成水墨骨架、剪影或 3D 角色。还可以加入动作轨迹对比、历史成长记录和个性化形象，让数字小人成为用户训练档案的一部分。

### 14.5 文化内容后续如何升级？

后续会建立更系统的中原武术文化知识库，包括太极拳源流、代表人物、流派特点、招式文化、少林武术、河洛文化、宋代体育民俗和文旅路线。同时增加知识问答、任务路线和研学课程，让文化模块不仅能看，还能测、能学、能分享。

## 15. 现场高压追问回答模板

### 15.1 如果评委问：“你们这个是不是包装得很好，但技术其实很简单？”

可以这样答：老师这个问题很关键。我们确实不是从零训练一个大型姿态识别模型，底层识别可以使用成熟开源方案。但我们的工作重点不只是调用模型，而是把通用姿态关键点转化为太极拳场景中的可解释评测，包括标准动作模板、四维评分、推手交互规则、数字小人可视化和文化研学闭环。智能文化赛道看重的是技术和文化场景的结合，我们的创新点正是在这个结合过程中形成的。

### 15.2 如果评委问：“你们现在到底完成到什么程度？”

可以这样答：目前完成的是一个可运行的 Web 原型，包括首页、AI 跟练、推手对练、数字小人、招式课程、文化地图和训练报告等主要页面，核心交互可以现场演示。技术上已经设计并实现了关键点识别接入路径、四维评分逻辑、标准动作校准、大模型建议接口和本地容错机制。我们也明确当前还不是完整商业系统，后续需要补充专业动作数据、专家评分和真实用户测试。

### 15.3 如果评委问：“你们的数据从哪里来？”

可以这样答：初赛阶段主要使用标准动作模板、预制演示数据和团队测试数据来验证功能闭环。后续计划的数据来源包括三类：太极拳教师或武术社团成员录制的标准动作视频，普通用户和团队成员录制的不同质量练习视频，以及推手模块产生的点击和反应时间数据。我们会用专家评分对系统评分进行校准，这是后续提升可信度的关键。

### 15.4 如果评委问：“这个项目和 AI 有多大关系？”

可以这样答：AI 不是装饰，而是贯穿动作输入到反馈输出。首先，姿态识别把视频中的人转成关键点，这是计算机视觉 AI；其次，动作评分把关键点转成姿态、重心、节奏、协调等可解释指标，这是面向太极场景的智能分析；最后，大模型把结构化评分转成个性化训练建议和文化解释。也就是说，AI 既负责“看懂动作”，也负责“解释动作”。

### 15.5 如果评委问：“为什么不说它已经能准确评测？”

可以这样答：因为我们希望表达更严谨。太极拳评测涉及专业动作标准、流派差异和专家经验，不能只凭一个原型就说完全准确。我们现在能证明的是：技术路径可行，功能闭环完整，评分指标合理，演示原型可运行。要达到专业准确，需要后续引入专家评分数据进行校准。这个边界说清楚，反而更符合科研和工程态度。

### 15.6 如果评委问：“最核心创新到底是哪一个？”

可以这样答：如果只能选一个，我认为是“把太极文化从静态展示变成动态参与”。具体落到功能上，就是 AI 跟练和虚拟推手。AI 跟练让用户的身体动作进入系统，被识别、评分和反馈；虚拟推手把借力化力、虚实转换这些抽象概念变成可交互体验。两者结合，体现了智能技术对传统文化传播方式的改变。

### 15.7 如果评委问：“为什么要做中原武术文化，不只做太极评分？”

可以这样答：如果只做太极评分，它更像一个运动训练工具；加入中原武术文化研学后，它才更符合智能文化赛道。太极拳本身就有深厚文化内涵，而河南又有陈家沟、少林寺、河洛文化等资源。我们希望用户在练动作的同时理解文化背景，让技术不仅服务运动纠错，也服务传统文化传播。

### 15.8 如果评委问：“未来你们怎么真正落地？”

可以这样答：落地分三步。第一步是把原型做稳，保证摄像头识别、评分、报告和文化地图完整可用。第二步是和体育老师或武术社团合作，建立标准动作库和专家评分数据，提高评分可信度。第三步是根据场景做不同版本，例如校园教学版、文旅大屏版、研学活动版和个人训练版。这样从技术、内容和场景三方面推进落地。

## 16. 现场演示应急回答

### 16.1 摄像头打不开怎么办？

可以说：现场浏览器权限和设备环境有时不稳定，所以我们设计了上传视频和模拟演示路径。摄像头跟练是目标交互方式，上传视频和模拟骨架用于保证演示稳定。工程上我们不希望因为现场权限问题影响评委理解核心流程，所以准备了多种输入方式。

### 16.2 Pose 模型加载失败怎么办？

可以说：Pose 模型加载需要网络和浏览器环境支持，如果加载失败，系统会自动切换到模拟骨架和本地评分演示。这不是功能缺失，而是我们为比赛现场准备的容错机制。真实部署时可以把模型文件本地化，减少网络依赖。

### 16.3 大模型接口不可用怎么办？

可以说：系统会使用本地建议模式，根据当前招式和评分生成兜底建议。配置密钥后才调用大模型。这样既保护密钥安全，也保证无网络时项目可运行。

### 16.4 分数波动很大怎么办？

可以说：姿态识别会受光照、入镜完整度和关键点抖动影响，原型阶段分数波动是正常问题。后续会通过关键点平滑、置信度过滤、时间窗口平均和专家数据校准来提高稳定性。

## 20. 展板逐区讲解专项

这一部分专门对应现场展板。答辩时评委很可能会直接指着展板问：“这个模块是什么意思？”“这个公式怎么来的？”“这个截图是不是真实系统？”所以每个版块都要准备一段稳定回答。

### 20.1 展板标题区怎么讲？

展板标题是“太极智练”，副标题是“AI 太极拳动作评测与中原武术文化研学平台”，下面列了五个关键词：人工智能、太极拳、虚拟对练、数字小人、中原文化。

可以这样讲：我们这个作品的核心不是单纯做太极介绍，而是把太极拳动作作为入口，用人工智能做姿态识别和动作评测，再通过虚拟推手、数字小人和文化地图，把中原武术文化变成可参与、可反馈、可传播的体验。标题区的五个关键词分别对应项目的技术基础、文化对象、互动创新、个性化展示和地域文化特色。

如果评委问“为什么标题用太极智练”，回答：太极代表项目的文化和动作对象，智练代表智能训练、智能评测和智慧研学。我们希望表达的是“用 AI 辅助太极拳学习，用交互方式传播中原武术文化”。

### 20.2 “一、创意说明”怎么讲？

展板创意说明里有一句很关键：“构建‘边练、边评、边玩、边学’的智能文化创意平台。”这句话应该作为主线背下来。

可以这样讲：这一块说明的是项目为什么存在。传统太极学习主要靠老师示范和视频模仿，用户很难及时知道自己动作哪里有问题；传统文化网页又主要是图文展示，用户参与感不足。所以我们把太极拳学习作为入口，让用户边练动作，边得到评分和纠错；边玩虚拟推手，边理解借力化力；边生成数字小人，边形成个人复盘；边解锁文化卡片，边学习中原武术文化。这样就实现了从“静态观看文化”到“动态参与文化”的转变。

如果评委问“创意到底新在哪里”，回答：新意不是只把太极文化放到网页上，而是把用户动作引入系统，让文化体验和身体参与绑定。用户练完动作后才解锁文化内容，这比单纯阅读更有参与感。

如果评委问“你们为什么说是智能文化创意平台”，回答：智能体现在姿态识别、动作评分、推手判定和 AI 建议；文化体现在太极招式、中原武术地图、文化卡片和研学内容；创意体现在把二者做成了训练闭环。

### 20.3 “二、核心功能”怎么讲？

展板上列了五个核心功能：AI 太极跟练评测、AI 太极推手对练、我的太极数字小人、太极招式课程、中原武术文化地图。

可以这样讲：这五个功能不是孤立页面，而是一个学习闭环。AI 跟练负责动作输入和评分反馈；AI 推手负责把太极推手思想变成互动体验；数字小人负责把用户动作转成个性化可视化结果；招式课程负责解决用户不知道怎么学的问题；文化地图负责把训练结果和中原武术文化连接起来。

**AI 太极跟练评测**  
展板写的是“摄像头识别动作，实时评分纠错”。回答时要强调：用户可以摄像头跟练或上传视频，系统提取人体关键点，和标准动作模板对比后输出评分和建议。当前原型有真实识别接入路径，也有演示和容错数据，不能说已经完全专业裁判级。

**AI 太极推手对练**  
展板写的是“虚拟对手互动点击，体验推手化解”。回答时要强调：推手模块把“掤、捋、挤、按”“借力化力”这些抽象概念变成了点击热点、倒计时、判定反馈和连击得分。它是文化概念交互化，不只是小游戏。

**我的太极数字小人**  
展板写的是“上传视频生成专属数字小人”。回答时要强调：它用于个性化复盘，把用户动作转成水墨骨架和动作轨迹。当前原型展示流程，后续接入真实逐帧关键点后可以由用户视频真正驱动数字小人。

**太极招式课程**  
展板写的是“分解教学 + 文化内涵，系统学习”。回答时要强调：课程不只是教学列表，而是把起势、云手、单鞭、白鹤亮翅、收势的动作要点、常见错误和文化含义结构化，用户学完后进入跟练。

**中原武术文化地图**  
展板写的是“文化地标 + 解锁卡片，研学中原文化”。回答时要强调：地图包含陈家沟、少林寺、河洛文化等节点，文化内容由训练行为触发，避免变成静态介绍。

### 20.4 “三、系统总体架构”怎么讲？

展板系统架构分为：用户交互层、数据采集层、AI 识别与分析层、动作评测与决策层、文化融合层、应用展示层。

可以这样讲：这张图说明的是数据怎么从用户动作一路变成评分、报告和文化内容。用户首先在交互层进行跟练评测、推手对练、视频上传和文化浏览；数据采集层获取摄像头视频、上传视频、点击行为和训练记录；AI 识别与分析层进行人体关键点检测、骨架姿态提取、动作轨迹提取和重心变化分析；动作评测与决策层输出姿态标准度、重心稳定性、节奏匹配度等评分，并对推手点击做匹配判定；文化融合层把评分和动作结果关联到招式文化、中原文化地图、文化卡片和知识问答；最后在应用展示层形成跟练页面、推手对练场、数字小人、招式课程、文化地图和训练报告。

如果评委问“为什么要分这么多层”，回答：因为项目不是单页面展示，而是从数据输入、AI 分析、评分决策到文化展示的完整链路。分层后能清楚说明每一层的输入输出，也方便后续把前端原型升级成真实后端和数据库系统。

如果评委问“文化融合层为什么在评分层后面”，回答：我们的文化内容不是孤立展示，而是由训练结果触发。比如用户完成云手训练后再解锁虚实相生文化卡片，完成推手后再解释借力化力，所以文化层接在评测和决策之后。

如果评委问“知识问答现在有没有实现”，回答要稳：当前原型重点实现文化地图和卡片展示，知识问答是展板中规划的扩展能力，后续可以结合大模型或知识库实现中原武术文化问答。

### 20.5 “四、动作评测模型”怎么讲？

展板动作评测模型流程是：输入视频 -> 关键点提取 -> 特征计算 -> 标准动作对比 -> 多维评分融合 -> 输出结果。

可以这样讲：动作评测模型是项目的技术核心。用户输入视频或摄像头画面后，系统先提取人体关键点，包括肩、肘、腕、髋、膝、踝等。然后基于关键点计算动作特征，例如手臂开合、膝关节角度、肩髋对齐、髋部中心摆动和运动节奏。接着和标准动作模板进行对比，最后融合成多维评分并输出训练报告。

展板公式是：`Score = 0.35Sp + 0.25Sb + 0.20Sr + 0.20Sc`。

可以这样解释：

Sp 是姿态标准度，表示用户动作形态和标准动作的接近程度。  
Sb 是重心稳定性，表示动作过程中身体重心是否平稳。  
Sr 是节奏匹配度，表示动作速度和标准动作节奏是否一致。  
Sc 是肢体协调性，表示上肢、下肢和躯干配合是否协调。

如果评委问“为什么姿态标准度权重最高”，回答：初学者首先要解决动作形态是否基本正确的问题，所以姿态标准度权重略高。但太极不是摆姿势，重心、节奏和协调也很重要，所以后三项也占比较大。

如果评委问“展板公式是 0.35，但报告里有 0.30，哪个为准”，回答：四个指标体系是一致的，权重是研究阶段的可调参数。展板版本为了突出初学阶段的姿态标准度，把 Sp 设置为 0.35；报告中的 0.30 是另一版设计。最终权重需要根据专家评分和真实数据校准后统一。答辩时不要说某个权重已经是最终标准，要说“权重可调、后续校准”。

如果评委问“雷达图上有上肢协调性、下肢稳定性，公式里为什么没有”，回答：雷达图为了展示更细的可视化效果，把协调性和稳定性做了细分；在公式层面，上肢协调性可以归入 Sc 肢体协调性，下肢稳定性可以归入 Sb 重心稳定性或作为其子指标。也就是说，展示维度可以细分，综合评分仍然可以归并为四个核心指标。

如果评委问“你们怎么保证评分不是随便写的”，回答：当前评分用于原型演示和训练辅助，不等于专业裁判分；但它不是随便写的，而是基于人体关键点、动作特征和标准模板差异生成。后续会用专业老师标准动作和专家评分样本来校准权重与阈值。

### 20.6 “五、AI 太极推手对练流程”怎么讲？

展板流程是：系统虚拟小人出招 -> 显示应对提示 -> 用户点击关键部位 -> 系统判定正确/错误 -> 化解成功得分提升 -> 生成推手报告。

可以这样讲：推手流程是我们把太极推手思想交互化的具体路径。传统推手强调听劲、化劲、借力化力，但初学者很难直接理解。我们让系统虚拟小人先出招，然后给出应对提示，用户在身体热点区域中点击关键部位。系统根据点击部位和反应时间判断是否化解成功。成功后加分和连击，失败后提示正确部位和动作原则，最后生成推手报告。

如果评委问“点击关键部位具体指什么”，回答：比如肩肘、手腕、胸前、腰胯、脚步等热点。不同来势对应不同应对部位，例如按劲下压更强调腰胯和重心控制，捋劲牵引更强调手腕方向转换。

如果评委问“这是不是太简单了”，回答：当前点击式交互是初赛原型，用来验证“推手文化概念能否转化为可理解的交互体验”。后续可以升级为摄像头动作响应，让用户通过真实后坐、转腰、沉胯、抬臂等动作完成化解。

如果评委问“推手报告记录什么”，回答：可以记录出招类型、点击部位、反应时间、成功率、连击数和错误类型，再和训练报告结合，形成用户对推手逻辑的学习反馈。

### 20.7 “六、关键创新点”怎么讲？

展板列了四个创新点：AI 实时动作评测、创新推手互动模式、用户数字小人生成、文化与训练深度融合。

**创新点 1：AI 实时动作评测**  
讲法：基于人体姿态识别和多维评分模型，系统可以实时反馈动作问题，实现智能化太极拳教学。这里要强调“可解释反馈”，不是只给一个分数，而是告诉用户姿态、重心、节奏、协调哪个维度需要改。

**创新点 2：创新推手互动模式**  
讲法：我们设计了可点击式推手对练场，把传统推手中的力点判断和化解逻辑转成互动体验，增强趣味性和学习性。这个创新点最适合现场演示，因为评委能直接看到用户如何参与。

**创新点 3：用户数字小人生成**  
讲法：用户上传动作视频后，可以生成水墨风格数字小人，展示个人动作轨迹，增强参与感和成就感。它让用户不只是看老师动作，也能看到自己的动作被数字化表达。

**创新点 4：文化与训练深度融合**  
讲法：我们把中原武术文化与 AI 训练结合，用户完成训练后解锁文化卡片，实现“练中学，学中悟”。这点最能体现智能文化赛道，而不是单纯运动工具。

如果评委问“四个创新点哪个最核心”，回答：最核心的是“AI 动作评测 + 推手互动 + 文化解锁”形成闭环。如果只能选一个现场亮点，我会选推手互动，因为它把太极中最抽象的借力化力转成了可操作体验。

## 21. 展板高频追问补充

### 21.1 评委指着“AI 太极跟练评测”问：实时评分怎么实现？

回答：流程是摄像头或视频输入后，系统提取人体关键点，形成骨架结构，再计算手腕跨度、膝关节角度、肩髋对齐、髋部中心摆动和动作速度等特征。然后与标准动作模板对比，得到姿态标准度、重心稳定性、节奏匹配度和肢体协调性四项评分。当前是原型阶段，评分用于辅助反馈和演示，后续会用专家样本校准。

### 21.2 评委指着“动作评测模型”问：为什么要标准动作对比？

回答：因为动作评测必须有参照。系统不能只识别出人体骨架，还要知道用户正在练的招式应该是什么样。标准动作模板提供了动作姿态、节奏和重心变化的参考，用户动作和模板对齐后，才能判断偏差在哪里。

### 21.3 评委指着“多维评分融合”问：多维评分有什么好处？

回答：好处是可解释。如果只给用户一个 86 分，用户不知道该改哪里；多维评分能告诉用户是姿态、重心、节奏还是协调出了问题。太极拳本身也不是只看动作形态，还看重心转换、节奏连贯和肢体配合。

### 21.4 评委指着“虚拟推手”问：为什么叫 AI 太极推手？

回答：这里的 AI 不仅指虚拟对手视觉，而是指系统根据出招规则、用户点击位置、反应时间和匹配关系做出交互判定。它把推手中的应对逻辑转成规则化智能反馈。后续还可以根据用户表现自适应调整难度，进一步增强 AI 属性。

### 21.5 评委指着“数字小人”问：数字小人有什么实际用处？

回答：它主要有两个作用。第一是复盘，骨架和轨迹比原视频更容易看出动作路径和节奏问题。第二是参与感，用户看到自己的动作被生成成水墨风数字小人，会更有成就感，也更愿意继续训练和分享。

### 21.6 评委指着“招式课程”问：课程和评分有什么关系？

回答：课程提供动作要点和常见错误，评分负责检测用户练习过程中的表现。比如课程告诉用户云手要腰胯带动，评分中如果重心稳定性或协调性偏低，就会提示用户不要只摆手，要先让腰胯带动手臂。课程是学习入口，评分是反馈机制。

### 21.7 评委指着“文化地图”问：为什么这些文化点和太极训练有关？

回答：陈家沟代表太极拳源流，少林寺代表中原武术的重要符号，河洛文化可以关联阴阳变化和圆转开合，开封民俗体现传统体育生活场景，郑州数字文旅代表现代传播应用。我们把这些节点和训练任务绑定，让文化内容从动作体验中自然展开。

### 21.8 评委指着“训练报告中心”问：报告能生成什么？

回答：报告可以生成综合评分、分项评分、近期趋势、最低分项、训练建议和文化解锁信息。当前原型用演示数据展示报告结构，后续接入真实训练记录后，可以形成用户长期训练档案。

### 21.9 评委问：展板写“知识问答”，你们实现了吗？

回答：当前原型重点实现了文化地图、文化卡片和训练报告，知识问答属于后续扩展能力。它可以基于中原武术知识库和大模型实现，比如用户问“云手为什么体现虚实相生”，系统结合文化资料回答。

### 21.10 评委问：展板很完整，但你们项目最真实完成的是哪几块？

回答：目前真实完成并可演示的是 Web 原型页面和核心交互，包括首页、AI 跟练页面、推手对练场、数字小人页面、招式课程、文化地图和训练报告。技术上已经预留姿态识别、标准骨架校准和大模型建议接口。需要继续加强的是真实数据采集、专家评分校准和长期用户档案。

### 21.11 评委问：展板这么多功能，会不会太散？

回答：看起来功能多，但它们都围绕同一个闭环：动作学习、智能评测、互动训练、复盘展示、文化研学、报告反馈。AI 跟练是基础，推手是互动亮点，数字小人是个性化复盘，课程和地图是文化承载，报告是闭环总结，所以不是功能堆砌。

### 21.12 评委问：现场拿着展板讲，最应该强调哪条主线？

回答：建议强调“从静态观看文化到动态参与文化”。展板每一块都服务这条主线：创意说明提出边练边评边玩边学；核心功能展示参与方式；系统架构说明技术链路；动作模型说明 AI 如何评；推手流程说明文化如何互动；创新点总结差异；效果展示证明原型；成果影响说明价值。
